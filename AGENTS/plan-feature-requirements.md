# Plan feature requirements

Read `docs/code-style.md` before proposing code. Work out the spec with the user in chat: outcome, numbered observable requirements, failure cases, and non-goals. For each requirement, agree on what a failing and passing result looks like. Use the smallest change that satisfies the present cases. Identify the checks the feature will need.

Ask the user to approve the spec explicitly. Do not write tests or implementation first. Keep the approved spec in chat or in the agreed issue and carry its requirement IDs into the PR. Work on a feature branch, never `main`.
